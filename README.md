# Rhine Music Demo

基于 [LBEILC/RhineLabUI](https://github.com/LBEILC/RhineLabUI) 改造的本地音乐播放器原型，由 [RonaldDeng](https://github.com/RonaldDeng) 维护音乐适配。用实体 CD 盒般的三维卡片浏览专辑，保留原工程的开场、抽取、磨砂玻璃、旋转和拆解动效。

这是独立维护的音乐衍生版本，运行在本机；原项目在线站点展示的是上游档案终端。初始基于上游提交 [`5abab02`](https://github.com/LBEILC/RhineLabUI/commit/5abab02367465d9189f4ae65bcb6f17fdb5938f7)，保留原提交历史、作者署名与完整 [MIT License](LICENSE)。原项目介绍、截图、资源与许可说明保存在 [README.original.md](README.original.md)。

## 当前功能

- **真实本地曲库**：扫描指定文件夹，读取专辑、歌手、歌曲和封面；启动时增量检查新增、移除和变化的文件，音乐文件本身不改写。
- **专辑封面卡片**：每张卡片对应自己的封面，保留原始比例，允许留白。待选卡片额外抬起，让封面多露出一截；打开后可查看完整专辑。
- **按流派浏览**：左右切换流派，上下切换该流派的专辑。流派别名和人工归类保存在本地索引规则中，可合并“国语流行音乐”“华语流行音乐”等名称。
- **专辑详情**：`01 歌单` 中选歌，`02 专辑介绍` 查看有来源的介绍。展示发行年份、歌手、流派、CD 数、曲目数、格式与编码、位深与采样率、码率和时长。
- **极简播放**：右上角播放／暂停、停止按钮；无底部进度栏、上一首／下一首占位控件及收藏入口。连续播放当前专辑的曲目。
- **两套主题**：暖昼、深夜。深夜采用极简星点背景和白色透光盒体；独立模型查看器同步主题。
- **实体模型操作**：旋转、平移、缩放、清晰／磨砂、拆解和一键重组。封面随盖板一起拆开，保留内部环形结构。
- **声音与画质**：歌曲和氛围配乐淡入淡出衔接；歌曲、配乐、交互音效音量独立。保留画质预设、精细设置、减少动态效果和全屏。

最近的界面调整：长专辑名自适应字号，双语译名以较小字号分行；删除“完整封面 · 原始比例”说明小字。文字遮罩可见后的停留约为 **0.35 秒**，扫开仍为 **0.95 秒**，保留逐行节奏；`01 / 02` 页签保留内容淡入和下划线平移。

启动 Logo、欢迎 Logo 和扫描圆环已隔离播放器图标样式，恢复原尺寸。搜索按钮不再显示 `/` 提示，键盘快捷键仍可用。

不包含歌词、频谱、均衡器、在线搜歌或云同步。

## 帧率与画质

音乐场景已将同一帧的阴影生成合并为一次，环境遮蔽与景深处理复用该阴影；保留逐帧更新、现有材质和动画。画质偏好不自动降档。

“高”档在 Retina 屏幕可使用 2.5 倍边长的渲染缓冲，像素数为窗口的 6.25 倍，并开启 4096 阴影、环境遮蔽、景深及 SMAA。帧率偏低时可先尝试“原始”档，保留主要视觉效果；还需要提高流畅度时，再在精细设置中降低环境遮蔽分辨率或关闭景深。各项都有画面取舍，实际收益受窗口尺寸、场景和硬件影响。原因及验证记录见 [性能记录](verification/MUSIC-PERFORMANCE.md)。

## 本地运行

使用 **Node.js 22.12 或以上版本**、npm，以及支持 WebGL 2 的现代浏览器。修改代码可使用 VS Code；普通运行无需 Blender，也暂时不需要安装 foobar2000。

### Mac 双击启动

在 Finder 中双击根目录的 [启动音乐播放器.command](启动音乐播放器.command)，即可启动后台服务并打开系统默认浏览器。第一次会安装锁定依赖、构建界面；后续启动仅在需要时重新构建。服务就绪后可以关闭启动器的终端窗口。

启动器优先使用 `5175`，确认本工程的服务已经运行时直接复用，不重复启动、不重启歌曲；端口被其他程序占用时尝试后续空闲端口。运行日志保存在工程旁 `music-data/player-service.log`。已有服务的复用不会触发重建；开发中修改服务代码仍需手动重启。

如果下载 ZIP 后可执行权限丢失，在工程目录运行 `chmod +x 启动音乐播放器.command`。启动器需要系统已安装 Node.js；找不到时会显示安装提示。

### 命令行启动

克隆本仓库并进入工程目录；私有仓库需要使用有访问权限的 GitHub 账号：

```sh
git clone https://github.com/RonaldDeng/Rhine-Music-Demo.git
cd Rhine-Music-Demo
npm ci
npm run build
npm run music -- --port 5175
```

打开 [本地播放器](http://127.0.0.1:5175/)；直接进入专辑架可用 [专辑预览](http://127.0.0.1:5175/?scene=archive)。省略 `--port` 时服务默认使用 `5173`，以启动日志为准。端口占用时需手动换一个空闲端口。

本地音乐服务同时提供构建后的界面与音乐 API，只监听 `127.0.0.1`。`npm run dev` 和 `npm run preview` 单独运行仅提供前端，不能代替音乐服务扫描和播放本地曲库。修改前端后重新 `npm run build` 并刷新页面；修改服务脚本后重启音乐服务。

首次运行在“音乐库”中填写实际音乐目录（例如 macOS 的 `/Users/你的用户名/Music` 或 Windows 的 `D:\Music`），再保存并扫描。已保存的本地目录配置会继续使用。原版 `启动终端.cmd` 仍启动前端开发服务；音乐版请使用上面的命令。

上游仓库与其下载包对应原版；音乐功能以本仓库为准。

## 操作

| 操作 | 功能 |
| --- | --- |
| `← / →` | 切换流派，首尾循环 |
| `↑ / ↓` | 切换当前流派的专辑，首尾循环 |
| `Enter` 或“打开专辑” | 打开当前专辑 |
| `01 歌单` 中点击歌曲 | 从所选歌曲开始播放 |
| 右上播放／暂停、停止 | 控制歌曲；停止后恢复已启用的氛围配乐 |
| `/` 或“搜索” | 搜索本地曲库 |
| `Esc` | 关闭弹窗、退出查看器或返回专辑架 |
| “360° 查看专辑模型” | 打开独立查看器，拖动旋转、滚轮缩放、方向键平移 |
| 查看器“拆解／一键重组” | 分开或收回部件，封面跟随盖板 |
| 设置 | 调节播放音量、氛围配乐、音效和画质；提供介绍更新入口 |

## 曲库索引与在线资料

索引默认位于工程旁的 `music-data/`，不会把歌曲复制进工程；也可通过 `MUSIC_DATA_DIR` 指定缓存目录。曲库路径、索引、提取的封面和个人配置不提交到 Git。

| 文件 | 用途 |
| --- | --- |
| `config.json` | 音乐根目录、在线资料和可选播放桥接配置 |
| `library-index.json` | 专辑、曲目、封面引用、扫描缓存和资料来源 |
| `genre-rules.json` | 流派名称、别名及人工专辑归类，适合由 Codex 维护 |
| `artwork/` | 从音频内嵌图片提取的封面缓存 |

优先读取文件夹封面，再读取内嵌封面。每个含音频的文件夹作为一个专辑；同一文件夹内按 CD 标签排序，不同 CD 子文件夹目前分别识别。文件夹移动会产生新 ID。断开的根目录保留缓存，不当作整库删除。人工流派归类优先于自动结果，不反写歌曲标签。

**专辑介绍**：设置页提供“查询 / 更新专辑介绍”，查询中文、英文维基百科及 Wikidata，核对专辑名称、歌手和年份，保存正式条目介绍、来源链接和时间。无需 MusicBrainz 联系信息或 API Key；不会用音频 comment 冒充介绍。未找到、匹配不明确、网络失败会分别显示状态。

**流派及制作人员**：可选 MusicBrainz 补全，需要填写自己的联系邮箱或项目网址作为请求标识。默认关闭自动补全；只发送查询所需文字或公开实体 ID，不上传音乐文件。

截至 **2026-09-09**，介绍查询功能已实现，但测试环境的实际 API 请求出现连接超时，真实资料覆盖率仍待验证；本地浏览和播放可继续使用。接口、缓存和来源匹配细节见 [音乐服务说明](docs/MUSIC-SERVICE.md)。

## 音频能力与后续计划

可索引 FLAC、WAV、M4A、DSF、DFF 等格式的元数据；实际播放取决于浏览器的解码支持。M4A 是容器，界面区分 AAC 和 ALAC；读取到元数据不等于已经验证该格式的播放或无损输出。

目前实际验证的本地库包含 **26 张专辑、378 首曲目、26 张封面**，编码均为 M4A 内的 MPEG-4/AAC。FLAC、WAV、ALAC 的实际播放仍需对应文件验证。DSF/DFF 暂不能在此浏览器播放器中播放，DSD 输出方式延后确定。

Windows 后续考虑 **foobar2000 + Beefweb** 作为播放内核。目前只有可选本机代理入口，尚未完成真实 foobar 队列和输出接入，也没有验证 DAC、原生 DSD 或 DoP。更大范围的动画重设计放在第二阶段。

## 开发与验证

界面使用 **TypeScript + Three.js + Vite**，本地服务使用 Node.js 和 `music-metadata`。

| 文件 | 职责 |
| --- | --- |
| [src/main.ts](src/main.ts) | 音乐模式与原版入口路由 |
| [src/music-app.ts](src/music-app.ts)、[src/music.css](src/music.css) | 音乐界面、操作与设置 |
| [src/music-title.ts](src/music-title.ts) | 双语长标题布局 |
| [src/music-player.ts](src/music-player.ts) | 本地队列、播放和配乐衔接 |
| [src/scene.ts](src/scene.ts)、[src/cover-atlas.ts](src/cover-atlas.ts) | 三维阵列、独立封面映射与待选抬升 |
| [src/model-viewer.ts](src/model-viewer.ts)、[src/viewer-album-cover.ts](src/viewer-album-cover.ts) | 模型查看、盖板封面与拆解 |
| [scripts/music-server.mjs](scripts/music-server.mjs)、[scripts/music-library.mjs](scripts/music-library.mjs) | 本地接口、扫描、索引与分类 |
| [scripts/album-introductions.mjs](scripts/album-introductions.mjs) | 百科介绍检索及匹配 |
| [src/archive-main.ts](src/archive-main.ts) | 保留的原版档案终端 |

```sh
npm run build
npm run check:music
```

已通过 TypeScript 与生产构建、音乐库/API 和介绍匹配测试、动态阵列与封面比例检查、BGM 过渡回归。介绍测试使用替身数据，不代表真实百科查询成功。真实浏览器已检查封面、长标题、待选抬升、详情及模型拆解；跨平台解码与实机性能仍需单独验证。

原版对照入口为 [原版档案阵列](http://127.0.0.1:5175/?original=1&scene=archive)。历史截图与动图在 `docs/media/`，展示的是原版档案内容；最新音乐适配记录见 [功能核对](verification/MUSIC-FUNCTION-AUDIT.md) 和 [封面验证](verification/MUSIC-COVERS.md)。
