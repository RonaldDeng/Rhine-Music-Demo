# V0.4.1 · 目录与开场整理

后续列浏览位置开关与回位修复见 [列浏览回归](COLUMN-POSITION-V0.4.1.md)。下文是首次目录、开场整理的验证记录。

2026-10-07。本地副本，基于当日已经完成缩略图与搜索动效修复的 V0.4.0。没有公开发布。

## 整理范围

- 先将 V0.4.0 的演示、光照实验 `.command` 移到 `tools/launchers/`，同步入口说明和脚本工作目录；根目录只留 `启动音乐播放器.command`。演示脚本去掉版本绑定名称，光照入口去掉针对旧版本页面的复用探测，避免误打开另一个版本。
- 复制为独立 V0.4.1。保留源代码、模型源文件、运行资源、检查脚本、许可、历史设计与验证记录。原 V0.4.0 产品源码和构建未改写。
- 不复制原版本的 `node_modules/`、`dist/`、`promo/`、系统缓存文件；在新版重新安装锁定依赖并生成生产构建。私人宣传片原件留在 V0.4.0。工程旁的 `music-data-v3` 未复制、未写入。
- 升级应用 package/lock 版本、页面标题、诊断版本、演示标识和现行文档。模型 `music-case-v040.glb`、缓存协议目录、历史记录保留原版本标记。新增 `check:v041`；旧命令保留为兼容入口。

## 开场改动

中文由用户选定为「一张一张，慢慢听」，英文保留 `ONE ALBUM AT A TIME`。删除标语横线的节点、样式和动画轨。

开场移除独立的 RHINE MUSIC 品牌副本，直接使用主界面已有的 `.music-header > .music-identity > .music-brand`。字体、文字、坐标和响应式规则只有一份。开场期间保持真实 header 可见、提升图层并锁定交互；仅隐藏右侧导航，交接时只淡入导航，品牌不再淡出后重现。各子组的原有 visibility 与 inert 状态在跳过、重播和卸载后恢复。

原 11.6 秒片头节奏、6.32 秒开始绘制三维的门控、三维进场和跳过机制均保留。

## 验证

- `npm ci --no-audit --no-fund`：锁定依赖安装完成，启动器 `dependenciesReady` 返回 true。
- `npm run build`：TypeScript 与 Vite 生产构建通过，PWA 资源清单生成成功。保留已有大 bundle 提示。
- `node scripts/check-music-boot-timing.mjs`：共享品牌节点、时间线、跳过、快速重播、减少动态效果、过时回调及嵌套可见性/交互状态恢复通过。
- `npm run check:startup`：启动、渲染器、画质检查通过。补齐了继承测试夹具中遗漏的 `overviewUI.dispose` 依赖，并验证其只执行一次。
- `npm run check:overview`、`npm run check:interaction`：继承的缩略图与搜索动效检查通过。
- `node scripts/check-music-launcher.mjs`：13 项启动器检查通过；三个 `.command` 的 shell 语法与可执行权限通过。
- 使用临时空数据目录启动真实生产服务：健康接口识别为 V0.4.1 工程，首页为新版标题，首页引用的构建入口可访问；服务随后关闭。没有启动或扫描个人曲库。
- 源文件逐文件比较：此前的场景、搜索、缩略图、材质和音频实现保留；产品源码差异仅开场三个文件及 music-app 的两个版本标记。

浏览器使用独立的 6 张合成专辑、内置三种演示封面及静音音频，未接入个人音乐服务。检查了完整开场、设置重播、标语阶段跳过、减少动态效果直接结束，以及以下布局。品牌矩形在开场和结束后完全相同：
