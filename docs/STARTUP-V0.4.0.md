# V0.4.0 冷启动与重新载入排查

2026-10-03。用户反馈：首次冷启动严重卡顿，设置里重新载入无效，关闭页面再双击 command 才恢复满帧。只有一个 V0.4.0 候选，修复均在这个目录，没有覆盖历史版本，也没有上传 GitHub。

## 结论与证据边界

确认并修复了初始化阶段的封面上传和解码峰值、不可见三维渲染、重复初始化，以及首次原生编译与图形准备争用资源。新增明确的 GPU 释放路径，使设置内重载也会释放旧渲染资源。

实际复现了首次加载约 700–733 ms 的长帧；在本机内置浏览器没有复现“进入专辑架后一直低帧、直到关闭页面”的完整现象。原版在这套隔离条件下也会恢复 60 FPS，因此不能宣称已证明持续问题的唯一原因，也不能把缺少 dispose 直接等同于 GPU 泄漏。已询问具体浏览器、持续时长及重载按钮，记录时尚未收到回答。

## 已证实的问题与修复

1. **图集上传**：9×48 实例使用 4096×6912 RGBA 图集，即 108 MiB。旧代码每个封面完成后设置整个 CanvasTexture 的 needsUpdate；Three.js r183 对 CanvasTexture 走整图上传。事件会按帧合并，不能将 432 次回调直接说成实际 432 次 GPU 上传。现在首次只分配 GPU 存储，使用公共 copyTextureToTexture 逐格更新；动画时每帧最多 8×256² RGBA，即 2 MiB。稳定帧无上传。启动准备可每轮 64 格、16 MiB，最多 12 轮，轮间让出一帧。
2. **解码峰值**：旧 LRU 只限制已完成结果，不能限制等待中的原始大图。现在同时解码最多 3 张，选中图片优先；原图解码后缩放并缓存为背景最长边 256px、选中最长边 1024px 的图像，已完成缓存最多 16 MiB。此限制不包含解码器临时原图及 GPU 内存。重置和销毁会取消排队及活动请求，晚到结果不能复活。新槽位的纹理尚未上传时隐藏旧图，防止短暂贴错专辑。
3. **画质覆盖**：全局 16× 过滤曾覆盖图集自身的 1× 限制，引发额外整图上传并破坏隔格采样保护。现在尊重纹理自有上限；默认画质、阴影、景深和透射分辨率未降低。
4. **首次渲染**：以前在开场计时开始后才触发首轮 GPU 工作。现在加载提示期间异步预编译实际材质，有限等待可见封面，再绘制两帧初始化阴影、透射、AO 与景深；完成后才启动开场时钟。初始化仍有真实成本，没有把它说成零等待。
5. **二维序章**：旧主循环忽略 renderScene 开关。隔离执行真实生产函数，61 个明确不应渲染的帧仍提交了 61 次三维场景。现在二维底纸完全不透明的前 6.32 s 不提交 WebGL；消退时恢复，保留原 5.2 s 三维段。
6. **重复与争用**：删除 load 后第二次 refreshLibrary；默认浏览器输出不在图形初始化时探测并编译 Swift，打开输出设置才探测；已保存原生输出依然在图形准备后恢复。v3/v4 标签结构兼容，复用未变化的缓存，新增 APE、修改文件及不兼容 v2 仍正常读取。
7. **扫描后的硬刷新**：扫描结果本来已经原地应用，原逻辑又在 2 s 后重载整页，重复创建场景。现在仅应用扫描结果并提示完成。
8. **页面生命周期**：设置“重新载入界面”和普通卸载主动销毁封面、几何、材质、后处理、阴影与 renderer，并释放 WebGL context；隐藏页暂停 RAF 和索引轮询，歌曲继续播放；BFCache 隐藏只暂停，返回复用，不销毁。迟到的异步请求不能在销毁后创建资源或排新轮询。
9. **统计误差**：旧首帧 FPS 把全部加载时间计入分母，曾在等待 30 s 的模拟里显示 0 FPS；隐藏恢复也把整个后台时间加进文字时钟。现在统计从首个实际帧开始，后台归零；文字步长最多 50 ms。增加近 240 帧的 p50/p95/max 与 CPU 提交耗时，后者不称为 GPU 时间。
10. **预热期间扫描完成**：首次索引曾在场景仍未 ready 时就排后续轮询；这时扫描完成会更新界面数据，却跳过三维刷新，导致真实列沿用旧数量。现在准备阶段只接受首个强制快照，完成后才恢复普通轮询；片头交接前继续保持场景稳定。联合回归执行生产 start/loadLibrary/receiveLibrary/applyLibrary，验证扫描从 1 张变 3 张时交接后界面与三维同步为 3，初始 scene.load 只有一次。

没有发现同一页面启动多个主 RAF 循环，也没有发现稳定画面一直重复上传封面的确定性循环。PWA 音乐入口本身不注册旧档案的离线 worker；是否仍受旧 worker 控制列入诊断，而不是未经复现就认定为原因。

## 实际浏览器对照

脚本 `scripts/serve-startup-review.mjs` 提供独立的 96 张 2048×2048 测试封面和 8 个分类，不读私人音乐。测试用同一 Three.js 构建质量、填充模式和默认效果，HTTP 返回 no-store；图像为 FFmpeg testsrc2 生成的图案。同一浏览器进程可能复用驱动着色器缓存，因此这属于新页面/资源加载对照，不冒充重新开机、全新驱动缓存或用户 Safari 的复现。

- 未优化初次记录：1280×720 渲染缓冲，峰值 700.1 ms；另一次默认密度、1920×1080 缓冲记录峰值 733.4 ms。其后稳定窗口约 59.9–60.1 FPS。
- 优化版首次记录：1280×720 CSS 视口，默认 1.5×、1920×1080 渲染缓冲，准备约 1243 ms；准备/序章起始窗口最大 383.3 ms。开场正常段与完成后窗口约 59.9–60.1 FPS，稳定最大帧约 18.7 ms。
- 设置内点击“重新载入界面”：稳定窗口约 59.9–60.1 FPS，最大帧约 18.8 ms；页面只有一个 canvas。
- 关闭页面重新打开：稳定窗口约 59.9–60.1 FPS，最大帧约 18.8 ms，与设置内重载一致。
- 三种优化路径没有通过改为“性能”画质取巧。首次 GPU 准备仍有 133–383 ms 的窗口峰值；稳定阶段没有由这些加载工作造成的重复长帧。
- 实际封面统计：peakDecodes=3，缓存约 12 MiB，432 格共上传 108 MiB tile payload，7 个初始化批次；完成后 pending/dirty=0、上传计数保持不变。这里是显式记录的像素载荷，不是 GPU 总显存测量。

原始样本保存在 `docs/media/v0.4.0/startup/`。时间序列保留起始 50 个窗口和近期窗口；普通刷新首轮采集不完整的文件不作为启动峰值证据。不同运行之间不作百分比性能提升保证。

最终构建复核：`final-build.json` 记录初始化约 823 ms，首次准备结束的 `gl.getError()` 为 0，稳定帧 60 FPS、p95 16.8 ms、最大 18.6 ms。只有一个 canvas，WebGL context 未丢失；此计数来自初始化后的单次检查，不额外逐帧同步 GPU。再次用内置实际封面核对正反方向、横竖图比例及真实列的 2+1 张数量，截图为 `overview-realistic-final.png`。

补充扫描与预热竞争修复后的最终产物再次复核：`final-lifecycle-build.json` 记录准备约 849 ms、GL 错误 0、稳定 60 FPS、p95 18.2 ms、最大 18.7 ms、单一 canvas；图集仍为 7 批且完成后无待上传格。

复现生成图案的隔离测试：在项目目录运行以下命令，再用浏览器打开脚本打印的本地地址。生产音乐库不会接入该服务；应保持相同画质与视口比较。

```sh
mkdir -p /tmp/rhine-v040-startup
ffmpeg -f lavfi -i testsrc2=size=2048x2048 -frames:v 1 -q:v 3 /tmp/rhine-v040-startup/cover.jpg
node scripts/serve-startup-review.mjs dist 5404
```

若测试图已存在，可直接运行服务。原版对照使用修复前保存的 dist 快照，不能用当前 dist 冒充基线。

## 回归与使用方式

`npm run check:startup` 执行真实生产函数的 AST 回归与统计器测试：601 帧只有 1 个续帧、601 个不透明片头帧为 0 次场景提交、300 次恢复不叠循环、四处异步启动销毁边界、后台数据请求、初始隐藏加载、BFCache、GPU 预热预算及释放幂等性。另有封面并发/上传/取消回归、曲库缓存兼容和播放器卸载测试。Mock GPU 断言与真实浏览器帧时间分别记录，不混称硬件测量。

`npm run build`（含 TypeScript 检查）和完整 `npm run check:v040` 均退出 0。后者启用了真实 APE 测试文件，覆盖音频、封面、模型、缩略图与真实列、启动生命周期、动效、光照、窗口适配、资料和启动器。终审补充第 10 项后，再次通过 `check:startup` 与生产构建。完整检查、最后生命周期回归和构建输出保存在 `docs/verification-v040-startup.txt`。构建仍有原有的大包体积提示，未把该提示当成帧率问题的证据。

如果仍出现低帧：在保持卡顿现场时进入设置底部，点击“复制性能诊断”。文本包含浏览器、视口、画质、近期帧时间、初始化和图集状态、是否有 service worker；不含音乐文件路径、曲名或封面。先复制再重载，能保留问题现场。项目不会自动上传这些内容。

不承诺所有设备、浏览器与分辨率都为 60 FPS。本轮没有触碰浏览器硬件加速、系统省电设置或用户其他页面，也没有靠清空用户存储恢复性能。
